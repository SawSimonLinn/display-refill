## Local integration work after choice

1. Add a provider-specific VisionAdapter implementing provider/model and `analyze(request, signal)`. Input already includes private validated JPEG bytes/dimensions, optional canonical reference and pinned slot IDs/geometry/product hints; targets and triggers are excluded. Use buildVisionPrompt and strict output schema. Do not send scan/store identifiers unless necessary; slot IDs suffice. Encode bytes inline instead of exposing Storage URLs. Never log bodies, prompts, photos or raw provider errors.
2. Map HTTP envelope structured output to `{raw, usage}`; handle refusals, incomplete output, absent reference, malformed JSON and schema rejection. Enforce transport response bound **before** buffering/parsing (current validator's 256 KiB bound is post-materialization), image limits, output-token ceiling and AbortSignal. Map auth/config/invalid-request permanent errors vs 429/network/5xx retryable VisionProviderError; parse bounded Retry-After. SDK retries must not multiply durable queue retries.
3. Extend factory/config validation for selected provider, required secret/model, approved endpoint/region and request limits; make the enablement explicit. Preserve pipeline strict validator, normalization and SQL revalidation, review-v1 threshold .80, count-v1/schema 1. Create new prompt/policy versions when tuning; persist snapshot not moving alias. Synthetic labeling must remain provider-derived.
4. Current pipeline has 45 s deadline, 20 s heartbeat/90 s lease, generation fencing and bounded database retries. Client timeout/fencing cannot guarantee external cancellation or avoid billing. Global monetary hard-stop is not implemented; provider project budgets may only alert. Before paid calls implement/check admission caps and bounded run size, set initial concurrency 1 and one worker replica; agree max calls/retries/output tokens and dollar ceiling with owner. Record canceled/failed usage even if no scan result commits.
5. Add offline transport tests with synthetic images: request excludes target/trigger/credentials; schema and missing/extra IDs; refusal/truncation; 401/403/429/5xx; ignored abort; response-size guard; usage redaction; no secret logs. Reuse DB fencing/takeover tests. Then authorized synthetic live smoke test (still paid if provider charges), development benchmark, frozen held-out benchmark and invoice reconciliation. No real counting claim before this sequence passes.
